Agrega el TERCER `useEffect`, con el mismo idioma silencioso/cancelled-flag que los dos existentes (líneas 32-51 y 54-70 del archivo actual), guardado por la condición compuesta `zona_status === 'encontrado' && zona_usos_disponibles === true` (nunca solo `zona_status`, ver Pitfall 1 del research: el caso Ñuñoa tiene `zona_status: 'encontrado'` pero `zona_usos_disponibles: false` y no hay texto que comparar) MÁS `destino_sii` no vacío (la ruta responde 400 si `usoPretendido` viene vacío):

```tsx
useEffect(() => {
  const zonaUtilizable = proyecto.zona_status === "encontrado" && proyecto.zona_usos_disponibles === true
  if (!zonaUtilizable || !proyecto.destino_sii?.trim()) {
    setCompat(null)
    return
  }
  let cancelled = false
  void (async () => {
    try {
      const res = await fetch(`/api/proyectos/${proyecto.id}/compatibilidad`, {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({ usoPretendido: proyecto.destino_sii }),
      })
      if (!res.ok) return
      const data = (await res.json()) as { estado: CompatEstado; justificacion: string }
      if (!cancelled) setCompat({ estado: data.estado, justificacion: data.justificacion })
    } catch {
      // silencioso: señal opcional, igual que los otros dos useEffect de este componente
    }
  })()
  return () => {
    cancelled = true
  }
}, [proyecto.id, proyecto.destino_sii, proyecto.zona_status, proyecto.zona_usos_disponibles])
```

El array de dependencias ya es la mitigación barata contra refetch en cada render que pide el research (Open Question 2): solo se re-ejecuta si cambian `destino_sii`, `zona_status` o `zona_usos_disponibles` — no en cada render del componente, igual que `ZonificacionCard` solo re-fetchea cuando cambia su campo de refresco.
